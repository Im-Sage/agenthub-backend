# AgentHub Backend

这是 AgentHub 的后端工程，当前已完成前五个阶段的后端最小闭环。

## 当前能力

```text
第一阶段：注册登录、JWT 鉴权、会话 CRUD、消息 CRUD
第二阶段：WebSocket 实时聊天和消息广播
第三阶段：@mock 指令、任务创建、Mock Agent 回复、任务状态推送
第四阶段：@orchestrator 指令、父子任务拆解、多 Agent 子任务执行、汇总回复
第五阶段：绑定 Git 仓库、准备本地 workspace、生成 git diff、保存并查询 Diff
第六阶段：接入阿里云百炼 / DashScope / 通义千问，支持 @qwen 真实 LLM 回复
第七阶段：基于 Diff 创建模拟 PR，生成本地预览部署，推送 PR 和部署事件
```

## 启动方式

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

服务启动后访问：

```text
http://127.0.0.1:8000/docs
```

## 第五阶段流程

第五阶段的目标是把 Agent 任务和代码仓库变更关联起来，跑通 Diff 展示链路。

当前实现先使用 Mock Diff，不直接让 Agent 修改真实业务代码。流程如下：

1. 用户登录，拿到 `access_token`。
2. 用户创建会话。
3. 用户发送 `@mock` 或 `@orchestrator` 消息，生成任务。
4. 用户绑定一个 Git 仓库：

```text
POST /api/repos
```

请求体可以传本地 Git 仓库路径：

```json
{
  "name": "demo-repo",
  "repo_url": "E:/demo/my-demo-repo",
  "default_branch": "main"
}
```

后端会把这个仓库 clone 到项目根目录下的：

```text
workspaces/repo-{repository_id}
```

5. 用户选择一个任务和一个仓库，生成代码变更：

```text
POST /api/code-changes/generate
```

请求体：

```json
{
  "task_id": 1,
  "repository_id": 1
}
```

6. 后端会在 workspace 中创建临时分支：

```text
agent-task-{task_id}
```

7. 后端写入一个演示文件：

```text
agenthub_changes/task_{task_id}.md
```

8. 后端执行：

```text
git diff
git diff --name-only
git rev-parse HEAD
```

9. 后端把 Diff 保存到 `code_changes` 表。
10. 如果 WebSocket 正在连接当前会话，会收到：

```text
code_change.generated
```

11. 前端可以查询某个任务的 Diff：

```text
GET /api/code-changes/{task_id}
```

## 第五阶段 Postman 测试

先准备一个本地 Git 仓库，例如：

```powershell
mkdir E:\demo\demo-repo
cd E:\demo\demo-repo
git init -b main
git config user.email "agenthub@example.com"
git config user.name "AgentHub"
"# Demo Repo" | Out-File README.md -Encoding utf8
git add README.md
git commit -m "init"
```

然后测试：

1. 登录拿 `access_token`。
2. 创建会话拿 `conversation_id`。
3. 发送一条任务消息：

```json
{
  "conversation_id": 1,
  "content": "@mock generate diff demo",
  "message_type": "text"
}
```

4. 查询任务：

```text
GET /api/tasks?conversation_id=1
```

5. 绑定仓库：

```text
POST /api/repos
```

请求体：

```json
{
  "name": "demo-repo",
  "repo_url": "E:/demo/demo-repo",
  "default_branch": "main"
}
```

6. 生成 Diff：

```text
POST /api/code-changes/generate
```

请求体：

```json
{
  "task_id": 1,
  "repository_id": 1
}
```

7. 查询 Diff：

```text
GET /api/code-changes/1
```

如果返回中包含这些字段，就说明第五阶段跑通：

```text
branch_name
changed_files
diff_text
status = generated
```

## 第六阶段流程

第六阶段开始接入真实 LLM。当前实现优先接阿里云百炼 / DashScope / 通义千问，并使用 OpenAI 兼容接口。

流程如下：

1. 在 `.env` 中配置阿里云百炼 API Key：

```text
ALIYUN_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
ALIYUN_MODEL=qwen-plus
ALIYUN_API_KEY=你的阿里云百炼APIKey
ALIYUN_TIMEOUT_SECONDS=60
```

2. 重启后端服务。
3. 用户登录并创建会话。
4. 用户发送 `@qwen` 消息：

```json
{
  "conversation_id": 1,
  "content": "@qwen 请用三句话介绍 AgentHub 的价值",
  "message_type": "text"
}
```

5. 后端创建 `qwen` 任务，并推送：

```text
task.created
task.updated RUNNING
```

6. 后端调用阿里通义千问接口。
7. 调用成功后：

```text
task.updated SUCCESS
message.created 真实 LLM 回复
```

8. 如果没有配置 Key 或接口调用失败：

```text
task.updated FAILED
```

错误原因会写入 `tasks.error_message`，可以通过：

```text
GET /api/tasks/{task_id}
```

查看。

## 第七阶段流程

第七阶段把“代码变更”继续推进到 PR 和预览部署。当前实现是本地可演示版本，不依赖 GitHub Token、Vercel Token 或云平台账号。

流程如下：

1. 先完成第五阶段，拿到一个 `code_change_id`。
2. 创建模拟 PR：

```text
POST /api/pull-requests
```

请求体：

```json
{
  "code_change_id": 1,
  "title": "AgentHub generated change",
  "body": "Generated by AgentHub"
}
```

后端会做这些事：

```text
切换到 code_change.branch_name
git add changed_files
git commit -m title
更新 code_changes.status = committed
保存 pull_requests 记录
生成 agenthub://... 形式的模拟 PR URL
WebSocket 推送 pull_request.created
```

3. 创建预览部署：

```text
POST /api/deployments
```

请求体：

```json
{
  "code_change_id": 1,
  "provider": "local"
}
```

后端会生成静态预览页：

```text
previews/deployment-{deployment_id}/index.html
```

并返回可访问 URL：

```text
/previews/deployment-{deployment_id}/index.html
```

4. 查询任务下的 PR：

```text
GET /api/pull-requests/{task_id}
```

5. 查询任务下的部署：

```text
GET /api/deployments/{task_id}
```

6. 如果 WebSocket 正在连接当前会话，会看到：

```text
code_change.generated
pull_request.created
deployment.created
```

## 注释保留策略

项目里已有学习注释会尽量保留。若文件因为编码问题导致中文注释乱码，处理方式是：

```text
先把原文件备份到 docs/comment_archive/
再把运行文件整理成 UTF-8
后续新增注释统一使用 UTF-8 中文
```

建议使用 VS Code 或 PyCharm 编辑，并确认文件编码为 `UTF-8`。

## 数据库配置

默认使用 SQLite：

```text
DATABASE_URL=sqlite:///./agenthub.db
```

项目会把这个相对路径解析到项目根目录，避免从不同目录启动时连接到错误数据库。

切换 MySQL 时可在 `.env` 中配置：

```text
DATABASE_URL=mysql+pymysql://root:password@127.0.0.1:3306/agenthub
```
